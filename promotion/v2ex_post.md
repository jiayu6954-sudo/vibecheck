### 版本 1：真实故事版

```
背景：

上周用 Cursor 写了个 Node.js 接口，看起来挺好，部署后发现：
- API key 直接写死在代码里（const apiKey = "sk-xxx"），被 GitHub Secret Scanning 警告了
- 数据库查询直接拼字符串（`SELECT * FROM users WHERE id=${userId}`），存在 SQL 注入
- 异步代码没 catch（await fetch(url)），线上报错才发现

这些都是"看起来能用"但其实有坑的代码。

---

问题：

每次都手动检查太累，直接问 Claude 又要写提示词（而且它不太会检查自己的"习惯"）。

---

做法：

周末写了个简单工具：
- 粘贴代码 → 3 秒出报告
- 告诉你哪里有风险 + 怎么改（可复制的修复代码）
- 用 DeepSeek API（国内访问快，便宜，¥0.005/次）
- 完全免费

地址：http://120.26.204.81:3000

---

实话实说：

这不是什么"革命性工具"，功能很基础：
- 只是包装了 AI API（写好了专业提示词 + 结构化输出）
- 不能替代人工代码审查
- 可能有误报
- 没有 IDE 插件（要手动复制粘贴）

---

请求：

如果你也用 AI 写代码，帮忙试试。
有啥问题直接说，骂也行，我想知道：
1. 这东西有没有人需要？
2. 应该往哪个方向改？

---

PS：
- 不收集代码（扫描完就没了）
- 开源计划中（先把核心功能做稳定）
- 如果觉得没用，麻烦也说一声为什么，帮助很大
```

4. 有没有不必要的依赖
5. 性能是否合理

但每次都要手动看，有点累。

---

做法：

写了个简单工具，自动检查这些常见问题：
http://120.26.204.81:3000

输入代码 → 3 秒出报告，告诉你：
- 发现了哪些问题（Critical/High/Medium/Low）
- 具体在哪里（代码位置）
- 怎么改（可复制的修复代码）

完全免费，用的是 DeepSeek API（便宜，国内快）。

---

局限性：

诚实说，功能很基础：
- 不能检测所有问题（只是辅助工具）

## 预期反应和应对

### 反应 1："这和直接问 Claude 有啥区别？"

**回答：**
```
诚实说，差别不大。

主要是：
1. 写好了专业提示词（针对 AI 代码问题）
2. 输出格式统一（评分 + 分类 + 修复代码）
3. 便宜 50 倍（¥0.005 vs ¥0.26）
4. 保存历史（可以追踪变化）

如果你很擅长写提示词，直接用 Claude 也行。
但大部分人（包括我）不太会写，所以做了这个。

不过你说得对，我们需要更多差异化功能（VS Code 插件、GitHub Action）。
正在考虑，欢迎建议。
```

### 反应 3："担心代码泄露"

**回答：**
```
理解你的担心。

现状：
- 代码只用于一次性扫描，不存储
- 走的是 DeepSeek API，我们不保存
- 服务器日志只记录扫描次数，不记录代码内容

计划：
- 开源核心代码（让大家看到我们怎么处理的）
- 提供本地部署版本（企业用户）

如果你担心，可以：
1. 用测试代码先试试
2. 等开源后自己部署
```

### 反应 4："误报怎么办？"

**回答：**
```
会有误报，因为底层是 AI。

建议：
- Critical/High 问题：一定要检查
- Medium/Low 问题：参考就好

如果发现误报，麻烦告诉我：
- 哪段代码
- 报了什么问题
- 为什么是误报

我会用这些数据改进提示词，降低误报率。
```
