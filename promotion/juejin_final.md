## 正文

### 一、代码审查的痛点

写完代码后，你通常怎么检查？

**方法 1：人工审查**
- ⏱️ 耗时：每次 30-60 分钟
- 😓 容易遗漏（特别是隐蔽的安全问题）
- 👥 需要经验（新手很难发现问题）

**方法 2：直接问 AI（Claude/ChatGPT）**
- ❌ 每次都要写提示词："帮我检查这段代码的安全问题、性能问题..."
- ❌ 输出不统一：有时候很详细，有时候太简略
- ❌ 没有结构化报告：无法追踪历史、对比改进
- ❌ 贵：Claude API ¥0.26/次，每天扫 10 次代码 = ¥78/月

**问题是：** 你需要的不是一个"聊天对象"，而是一个**专业的代码审查工具**。

#### 3. 典型问题检测

**示例 1：硬编码密钥（Critical）**

![硬编码检测](03-hardcoded-key.png)

```javascript
// ❌ 危险
const apiKey = "sk-abc123...";

// ✅ 安全
const apiKey = process.env.API_KEY;
```

**为什么重要？**
一旦推送到 GitHub，密钥立即泄露。去年有 23% 的数据泄露事件源于此。

---

**示例 2：SQL 注入风险（High）**

![SQL注入检测](04-sql-injection.png)

```javascript
// ❌ 不安全
const query = `SELECT * FROM users WHERE id=${userId}`;

// ✅ 安全
const query = 'SELECT * FROM users WHERE id=?';
db.query(query, [userId]);
```

**为什么重要？**
攻击者可以构造 `userId = "1 OR 1=1"`，获取整个用户表。

---

**示例 3：未处理的异步错误（Medium）**

![异步错误检测](05-async-error.png)

```javascript
// ❌ 缺少错误处理
await fetch(url);

// ✅ 添加错误处理
try {
  await fetch(url);
} catch (error) {
  console.error('Fetch failed:', error);
}
```

**为什么重要？**
未捕获的 Promise 会导致进程崩溃（Node.js）或页面卡死（浏览器）。

### 九、局限性（诚实说明）

**VibeCheck 不能做什么：**

❌ **不能替代人工代码审查**
- 复杂业务逻辑还是要人看
- AI 只能检测常见问题，不能理解业务需求

❌ **不能保证 100% 准确**
- 底层是 AI（DeepSeek），会有误报
- Critical/High 级别问题相对准确，Medium/Low 可能误报

❌ **不能检测所有漏洞**
- 只能检测常见的安全问题
- 零日漏洞、特定框架漏洞可能检测不出

❌ **目前功能基础**
- 没有 IDE 插件（要手动复制粘贴）
- 没有 CI/CD 集成
- 没有自定义规则

**我们的建议：**
- 用 VibeCheck 做第一轮自动检查
- 重要代码还是要人工审查
- Critical/High 问题一定要处理
