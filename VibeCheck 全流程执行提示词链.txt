VibeCheck 全流程执行提示词链
先回答你的问题：先从国内还是国外开始？
明确建议：先从国外英文市场起步，在国内做幕后指挥。

原因很简单：

搭建面向全球的产品，Vercel + Stripe + Reddit 没有地理限制。

国外市场支付链路成熟（Stripe 零开发成本）、目标用户聚集（r/vibecoding 8.9 万人）、有明确付费习惯，是完成 PMF 验证 的最低摩擦选择。

一旦国外跑通付费闭环（哪怕 MRR 只有 $200），你再用同一个技术底座、替换国内 API 和支付，复刻到国内，就是第二增长曲线。

国内先跑会面临 ICP 备案、支付资质、用户冷启动分散等额外摩擦，不适合“先验证再做大”的独立开发者节奏。

所以你的最优路径是：

以全球英文市场为第一战场，完成验证和最初现金流 → 同步搭建国内 API 适配层 → 第 8 周后以成熟的付费模型开辟国内版。

下面所有的提示词，都是按这个路径设计的。

你是一位全栈工程师。请在本地为我搭建 VibeCheck 的最小可行产品骨架。
要求：

   - 一个“扫描代码”按钮
   - 一个结果展示区域（默认隐藏，扫描后显示）

     {

   - 做好错误处理，如果 API 失败返回合适的错误消息
5. 添加 `.env.local` 文件示例，包含 `CLAUDE_API_KEY` 占位
6. 整个项目能通过 `npm run dev` 直接启动，不要有任何其他未实现的依赖

提示词 2：补充 Semgrep 轻量规则兜底（降低成本）
text
现在为我的 VibeCheck API 添加 Semgrep 规则扫描作为第一层过滤。
1. 在项目根目录创建一个 `rules/` 文件夹，里面有至少 4 条自定义 Semgrep 规则，专门检测 AI 生成代码常见问题：
   - 硬编码凭证（如 API Key、密码赋值）
   - SQL 字符串拼接（可能导致注入）
   - 使用 eval() 或 Function() 动态执行
   - 过长的函数（超过80行，作为可维护性警告）
2. 修改 `pages/api/scan.js`，使其逻辑变为：
   - 先在服务器端用 semgrep CLI 对传入代码片段进行扫描（可在 API 内通过 `exec` 调用 `semgrep --config rules/ --json -` 并传递代码到标准输入）
   - 如果 semgrep 发现 high/critical 问题，直接使用这些结果，不调用 Claude
   - 如果没有严重问题，或者 Semgrep 无法确定（需要语义理解），再调用 Claude 做深度分析
   - 最终返回结构保持原来的 JSON 格式，无论来自哪一层
3. 确保 `semgrep` 安装在本地开发环境，并在代码中添加指导如何安装（brew install semgrep 或 pip install semgrep）
4. 更新项目的依赖说明（README.md）

请输出所有新增或修改的文件内容。
提示词 3：添加 Supabase 认证和次数限制（后端硬限制）
text
现在为 VibeCheck 添加用户系统和后端每日次数硬限制，替代前端 localStorage 的软限制。
1. 集成 Supabase：
   - 使用 Supabase Auth（邮件密码模式）
   - 在 Supabase 中创建一个 `scans` 表，字段包括：id, user_id, created_at, code_snippet（不存源码，只存一个哈希或前100字符作为审计）,  scan_result (JSONB)
   - 创建一个 `subscriptions` 表：user_id, plan (free|pro), scans_today (整数), last_scan_date
2. 修改 `pages/index.js`：
   - 添加登录/注册表单（在扫描框上方，未登录状态下提示“登录后扫描”）
   - 登录后显示用户邮箱和计划状态
   - 按钮点击时调用 `/api/scan`，并附带用户的 access token
3. 修改 `pages/api/scan.js`：
   - 验证用户 token（从 Authorization 头中获取）
   - 从数据库读取用户今日扫描次数，免费用户限制为 3 次/天，Pro 用户无限次（但限制每天最多 50 次以防滥用）
   - 扫描成功后记录到 `scans` 表，更新 `subscriptions` 表中的计数
   - 返回剩余次数信息给前端
4. 添加 `lib/supabase.js` 初始化文件，使用环境变量 `NEXT_PUBLIC_SUPABASE_URL` 和 `NEXT_PUBLIC_SUPABASE_ANON_KEY` 以及 `SUPABASE_SERVICE_KEY`（仅后端用）
5. 在 `.env.local.example` 中列出所需的 Supabase 相关环境变量
